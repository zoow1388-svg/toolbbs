# 任务协议

## 派发必须包含

- `task_id`、`dispatch_id`、角色和目标
- 项目绝对路径、Codex `thread_id`、`host_id` 与 Git 基线
- 依赖任务及其已验证 `end_revision`
- 允许读取和修改的范围
- 当前授权级别
- 要求执行的验证
- 停止条件和回报格式

## 回报格式

执行任务应使用清晰标题或字段名返回事实性结构化文本。可以使用 Markdown，不要求执行任务手写严格 JSON。命令中的引号、反斜杠和换行必须保留原意。

总控在派发时已掌握 `thread_id` 和 `host_id`，必须把它们写入指令；执行任务不得自行猜测或返回 `unknown`。

总控必须保留原始回报，并按 [result-normalization.md](result-normalization.md) 生成可校验 JSON。格式问题由总控规范化，不应要求执行任务反复返工；事实缺失才属于返修。

规范化 JSON 是机器交换文件，不得直接作为面向用户的最终回报。总控必须先运行 `scripts/validate-result.ps1`；通过后再用 `scripts/render-result.ps1` 生成 UTF-8 中文 Markdown。校验失败或 Git 基线过期时，停止门禁并显示具体字段路径。

## 回报必须包含

- 任务编号、派发编号、实际项目路径、`thread_id` 和 `host_id`
- 当前分支、开始和结束提交
- 实际完成内容及修改文件
- 实际执行的命令、退出码和结果
- 测试、构建、启动、页面或接口验证
- 未执行项、日志或产物路径
- 阻塞原因、剩余风险和所需新授权
- 当前角色、实际检查修订、角色完成标准和未解决发现
- 结果生成时间

总控必须从实际文件、Git 和命令输出复核关键结论，不接受只有“完成”或“通过”的回报。

## 主动回传

派发信封必须提供不可变的 `callback.event_id`、目标总控任务 ID 和主机 ID。执行任务完成工作并形成最终回报后、结束本轮前，使用 `send_message_to_thread` 原样发送信封生成的单行 JSON。

总控只接受同时匹配工作流、任务、派发、来源线程、来源主机、目标线程和目标主机的 `completion_callback`。收到后保存原始消息、生成回执并返回相同事件 ID 的 `callback_ack`。相同事件的重复消息只复用既有状态，不得重复审查或派发。
